# 목소리 스타일 역추정: Voice Builder 없이 내 목소리 만들기 (검증)

**추천: 쓸 만합니다. 다만 Voice Builder를 대신한다고 약속하지 말고, "무료 실험 경로"로 내놓기를 권합니다.**

- Voice Builder(유료, 서버) 없이 공식 가중치만으로 Supertonic 스타일 벡터를 만들 수 있습니다. 맥 M4에서 목소리 하나에 약 12분 걸렸고, 결과 JSON은 앱의 "직접 만든 목소리 넣기"와 sherpa-onnx `voice.bin`에 그대로 들어갑니다.
- 최적화에 쓰지 않은 화자 인식 모델 둘(WeSpeaker, WavLM-SV)로 재면 이렇습니다(화자 4명 평균, Voice Builder 결과와 같은 문장 기준).
  - 기본 설정(c′)은 프리셋 고르기(0.55 / 0.73)보다 확실히 낫습니다(0.68 / 0.86).
  - Voice Builder(0.78 / 0.91)와의 차이는 절반 넘게 줄였습니다.
  - 한국어 화자(alphonse)는 Voice Builder와 잡음 범위 안에서 같습니다(0.77 / 0.94 대 0.79 / 0.94).
- **사람 귀로는 아직 안 들었습니다.** 지표는 같은 종류의 모델이라 함께 속을 수 있습니다. 결과 wav를 먼저 들어 보고 판단하세요(맨 아래 "다음 단계").
- 검증 없이 오래 돌리면 소리가 무너지는 경우가 있었습니다. 3초 녹음(nora)에서 받아쓰기 오류율(CER)이 0.58이 됐습니다. 그래서 기본값은 "혼합에서 시작 + 검증 문장으로 가장 좋은 시점 고르기"이고, 이 설정에서는 4명 모두 무너지지 않았습니다(CER 0.08 이하).

측정 환경과 재현:

- 측정일 2026-10-14~15. Apple M4 맥(16GB, MPS)에서 torch 2.14.1, onnx2torch 1.5.15, sherpa-onnx 1.13.8로 돌렸습니다.
- **코랩 GPU에서는 돌려 보지 않았습니다.** `colab.ipynb`는 맥에서 끝까지 돌려 본 명령(`fit` → `pack` → `eval --ref`)을 그대로 부르지만, 코랩에서 실행해 확인하지는 않았습니다.
- 재현: `voice_inversion.py` docstring대로 venv를 만들고 `sh spike/voice_inversion/run_all.sh`를 실행합니다(맥 M4에서 약 4시간).
  - 모델·가중치·결과 wav는 `~/.cache/epub-tts-spike/voice_inversion`(저장소 밖)에 생깁니다.
  - 수치는 `eval/<모델>/eval.json`에 있습니다.

## 방법

1. **모델을 PyTorch로 옮기기**: HF `Supertone/supertonic-{2,3}`의 fp32 ONNX 4개를 onnx2torch로 옮겼고, 막힌 곳은 둘뿐이었습니다.
   - onnx2torch 1.5.15에는 opset 19 변환기(Shape, Constant, Cast, Pad 등)가 없습니다. opset 19는 타입만 넓혔으므로 직전 버전 변환기를 그대로 씁니다.
   - Clip의 빈 선택 입력(`''`)과 Constant 노드의 min 값을 정적 값으로 읽지 못합니다. Constant를 initializer로 옮기고 빈 입력을 지웠습니다.
   - 결과는 onnxruntime과 최대 5e-5 차이(파형 진폭 0.3 기준)로 같습니다. MPS(맥 GPU)에서도 돌고, 비공식 supertonic-pytorch 재구현은 필요 없었습니다.
2. **(a) 가장 가까운 프리셋**: 프리셋 10개로 문장 5개(한국어 3, 녹음 언어 2)를 합성해, 대상 녹음과 ECAPA 코사인 유사도가 가장 높은 것을 고릅니다.
3. **(b) 혼합**: 프리셋 10개의 style_ttl·style_dp를 softmax 가중치로 섞고, 가중치 10개만 경사 하강으로 학습합니다(40회).
4. **(c) 역추정**: style_ttl [1,50,256] 전체를 학습합니다.
   - 손실 = 1 − cos(ECAPA(합성), ECAPA(녹음)) + 0.01 × (변화량 / 프리셋 간 표준편차)²의 평균.
   - 반복마다 최적화용 문장 2개(한국어 12개, 녹음 언어 6개 중 무작위)를 새 잡음 시드로 합성합니다. 합성은 flow-matching 4스텝(앱은 8스텝)이고, 텍스트 인코더 → vector estimator 4회 → 보코더 → ECAPA까지 역전파합니다. Adam lr 0.05(프리셋 간 표준편차 단위)입니다.
   - **(c)**: 가장 가까운 프리셋에서 시작해 300회 돌리고 마지막 값을 씁니다(처음 계획).
   - **(c′) 기본값**: 혼합에서 시작해 200회 돌립니다. 25회마다 검증 문장 3개(최적화·평가 문장과 겹치지 않음)를 8스텝으로 합성해 WavLM-SV 유사도를 재고, 가장 높았던 시점(0회 = 혼합 포함)을 씁니다.
   - style_dp는 길이(말 속도)만 정해 경사가 흐르지 않으므로 시작점 값을 그대로 씁니다.
   - 멜·DTW 손실은 넣지 않았습니다. 같은 문장을 읽은 녹음(대본)이 있어야 하는데 HF 샘플에는 대본이 없습니다.
5. **평가**: 스타일을 sherpa-onnx `generate_voices_bin.py`로 `voice.bin`에 넣고 앱 음성 팩 zip(`*.int8.onnx`, `tts.json`, `unicode_indexer.bin`, `voice.bin`, `LICENSE`, `voices.txt`)으로 묶습니다.
   - 그 팩을 **sherpa-onnx Python(int8, 앱과 같은 경로)으로 열어 sid를 골라 8스텝으로 합성**합니다. 아래 수치와 wav는 모두 이 경로로 나왔고, 프리셋 10개 뒤 sid 10번부터 붙인 스타일이 제대로 합성됩니다.
   - **WeSpeaker ResNet34**(sherpa-onnx 화자 모델): 어떤 방법에도 쓰지 않은 지표. 다른 사람끼리도 0.4~0.67이 나와 절대값보다 순서를 봅니다.
   - **WavLM-SV**(microsoft/wavlm-base-plus-sv): (a)~(c)에는 쓰지 않았고, (c′)에서는 시점을 고르는 데만 썼습니다.
   - **ECAPA**: 최적화 대상이라 부풀려집니다. 괄호 안 참고값으로만 봅니다.
   - **CER**: 0단계와 같은 한국어 Zipformer ASR로 잽니다. 발음이 망가졌는지 봅니다(프리셋은 0.01~0.09).
   - 문장: Voice Builder 결과 wav와 **같은 문장**(HF README의 짝, 녹음 언어) 1개와 한국어 4문장.
   - 대상: HF `audio_samples`의 luna(영어 여성, 12초), alphonse(한국어 노인 남성 캐릭터, 12초), keld(영어 뉴스 남성, 12초), nora(영어 상담원 여성, 3초).
   - 잡음 크기: 같은 스타일을 두 번 합성해 재면(예: F1과 luna.nearest) 0.03~0.04 차이가 납니다. 그보다 작은 차이는 구분하지 않습니다.

## 돌린 범위와 못 돌린 범위

| 항목 | 상태 |
|---|---|
| ONNX → PyTorch 변환, onnxruntime과 수치 대조 (v2, v3) | 맥에서 확인 |
| (a) 가장 가까운 프리셋, (b) 혼합, (c) 역추정 | 맥 MPS에서 실행. v3은 화자 4명과 길이 3·6초, v2는 화자 2명 |
| (c′) 기본값 | 맥에서 v3 화자 4명 실행. **v2는 안 함** |
| Voice Builder 결과와 같은 지표로 비교 | 맥에서 실행. Voice Builder 결과 wav는 v3만 공개됨 |
| `generate_voices_bin.py` → voice.bin → 앱 팩 zip → sherpa-onnx Python에서 sid로 합성 | 맥에서 확인. 위 평가 wav가 전부 이 경로로 나옴 |
| 사용자 녹음 경로 (`fit --ref` → `pack` → `eval --ref`, v2) | 맥에서 짧게(25회) 끝까지 확인 |
| 앱(안드로이드)에서 zip/JSON 가져오기 | **안 함**. 앱 코드는 이 작업 범위 밖이고, 형식만 앱의 `appendVoice`·`isSupertonicPack`·`floats`(중첩 배열 평탄화)에 맞춤 |
| 코랩 GPU 실행, 시간 측정 | **안 함**. 코랩 접근이 없어 노트북만 작성 |
| 녹음 1분·5분 | **못 함**. 공개 reference가 최대 12초 |
| 사람 청취 | **안 함**. wav만 남김 (`~/.cache/epub-tts-spike/voice_inversion/eval/<모델>/<화자>__<스타일>__<문장번호>.wav`, 0번이 Voice Builder와 같은 문장, 1~4번이 한국어. 같은 폴더에 `<화자>__reference.wav`, `<화자>__voice_builder.wav`) |

## 한계

- **지표는 사람 귀가 아닙니다.** 화자 인식 모델 셋이 대체로 같은 순서를 매기지만, 셋 다 "화자 임베딩"이라 함께 속을 수 있습니다. 청취 전에는 "Voice Builder에 가까울 수 있다"까지만 말할 수 있습니다.
- **음색 위주입니다.** 손실이 화자 임베딩뿐이라 말 속도와 억양 습관은 따라가지 않습니다. style_dp(말 속도)는 프리셋이나 혼합 값 그대로입니다. 대본이 있는 녹음이면 길이 맞추기(dp)와 멜/DTW 손실을 더할 수 있습니다.
- **시작점을 ECAPA가 고릅니다.** 4명 모두 ECAPA가 고른 프리셋이 최선이 아니었습니다. 검증 지표(WavLM)로 시작점을 고르는 쪽이 나을 것 같지만 해 보지 않았습니다.
- **대상은 4명, 최대 12초의 깨끗한 스튜디오 녹음입니다.** 집에서 폰으로 녹음한 소리(잔향, 잡음)에서는 ECAPA가 그 잡음까지 흉내 내게 만들 수 있습니다.
- **Supertonic 2와 3은 따로 만들어야 합니다.** 스타일 공간이 달라서 한쪽에서 만든 JSON을 다른 쪽에 넣으면 엉뚱한 목소리가 납니다(앱 사용 방법 8번과 같음).
- **최적화는 확률적입니다**(잡음 시드, MPS 비결정성). 같은 명령을 두 번 돌리면 혼합 가중치가 꽤 다르게 나왔습니다(luna: F1 0.72 + F4 0.21 대 F1 0.99).
- 역추정 중 로그에 찍히는 검증 값(`wavlm(검증)`, 이전 실행 로그에는 `held-out`)은 문장 2~3개, 시드 하나로 잰 것이라 흔들립니다. 위 표의 수치는 그 로그가 아니라 `eval`(sherpa int8, 5문장)에서 나왔습니다.

## 사용자 본인 녹음으로 실행하는 절차

`colab.ipynb`가 이 순서를 그대로 따릅니다(코랩 실행은 미확인). 자기 컴퓨터에서 하는 방법은 [docs/my-voice.md](../../docs/my-voice.md)에 있습니다(`fit`·`eval`의 `--ref`에 녹음 파일 여러 개를 적으면 이어 붙입니다).

1. **동의 문장**: 노트북 첫 칸에서 확인합니다. 녹음 첫 파일로도 남겨 두기를 권합니다.
   > 나는 이 녹음 속 목소리의 주인이며(또는 주인에게 동의를 받았으며), 이 목소리로 음성 합성 스타일을 만들어 내 기기에서 책을 읽는 데 쓰는 것에 동의합니다.
2. **녹음**: 조용한 방에서, 입에서 한 뼘 떨어져, 평소 책 읽는 속도와 톤으로 한국어 문장을 읽습니다.
   - 필요 녹음량: **최소 15초, 권장 1분 안팎**입니다. 검증한 것은 12초까지입니다.
   - 3초도 될 때가 있지만 무너질 위험이 큽니다. 1분 넘는 녹음은 10초씩 잘라 임베딩을 평균하므로 더 안정적일 것으로 보지만, 재지는 못했습니다.
   - 한 파일은 5~30초 wav로 하고, 잡음 제거·음악·효과는 넣지 않습니다.
   - 녹음 도우미(PRD V-2/V-3)를 만든다면 이 정도면 충분합니다: 문장 목록 보여 주기 → 문장마다 녹음 → 앞뒤 무음 자르기 → 음량 맞추기.
   - 이 방법은 대본을 쓰지 않으므로 문장을 정확히 읽었는지는 검사할 필요가 없습니다. 대본을 녹음과 함께 저장해 두면 나중에 말 속도·멜 손실을 더할 수 있습니다.
3. 구글 드라이브 `MyDrive/voice-reader/recordings`에 wav를 넣고, 코랩에서 GPU 런타임으로 노트북을 위에서부터 실행합니다.
   - `fit`: 기본값(c′)으로 nearest, blend, invert JSON 세 개를 드라이브 `out`에 씁니다.
   - `pack` + `eval --ref`: 앱 팩 zip을 만들고, 앱과 같은 int8 모델로 합성한 소리를 들려 줍니다. 내 녹음과의 유사도(WeSpeaker, WavLM)와 CER도 보여 줍니다.
   - invert의 CER이 0.1을 넘거나, WeSpeaker가 가장 좋은 프리셋보다 낮으면 그 결과는 쓰지 않습니다.
4. 귀로 고른 JSON의 이름을 `내 목소리.json`처럼 바꿔 폰으로 옮깁니다. 앱에서 **목소리** 버튼 → **직접 만든 목소리 넣기** → 동의 확인 → 같은 모델의 음성 팩 순서로 고릅니다.
